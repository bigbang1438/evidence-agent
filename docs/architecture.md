# 设计取舍与可复现检查

## 为什么保留标准库

项目关注工具执行边界、状态持久化和证据链，不需要把问题隐藏在多层框架中。HTTP、SQLite、BM25 与 Ollama 协议均可直接阅读；实际生产仍应使用成熟 Web 框架、身份认证、可取消任务与队列，标准库服务没有替代这些需求。

## 谁有写权限

模型仅拥有三项可申请能力。`task_create` 被工具层 `ApprovalRequired` 拦截后转为保存待确认请求。独立 HTTP 确认接口持有用户动作与 CSRF 验证上下文，并校验请求绑定的会话 ID；模型协议不包含审批 schema。确认事务先锁定待处理记录，再更新状态并写任务，唯一 `approval_id` 防止重放产生第二条任务。旧数据库通过新增可空 `conversation_id` 列保留原记录，旧未绑定请求不会显示为当前会话审批，也不能用新的会话 ID 直接批准。

文档提示注入可能影响模型提出的标题或答案，但不能构造新增工具或自动批准。待确认标题需要人检查。工具调用参数严格匹配 schema，不接受额外的 `approved`、URL、路径字段。程序没有工具动态注册入口。

## 如何限制循环

模型轮次与每个工具调用分别扣减步骤。一个包含三次 tool_calls 的模型消息会占四步；不会绕过预算。工具之间及模型响应之后检查剩余时间，网络请求设有限超时。总模型输入包含 system、历史、当前提问、assistant、tool observations 与 schema，最多 16,000 字符，超过后停止下一模型轮次。任务列表 observation 最多 20 条并明确标注截断；这不是精确 token 管理。超预算返回错误，既有待确认请求仍可能保留，用户可刷新处理；没有自动提交或“失败回滚所有外部动作”的虚假保证。

## 多轮上下文如何选取

每轮成功运行保存到 SQLite。下轮只选择本会话最后六轮用户问题 / 最终答案，从最新往前选择不超过 12,000 字符的完整对。历史工具调用不回放为新指令，隐含模型思考不读取也不保存。历史源引用编号属于各自运行，模型需在新一轮重新检索取得有效的新来源。

这是一种可解释的截断策略；长文可能失去早期事实。没有把“保存到 SQLite”描述成自动学习或长期语义记忆。

## 为什么没有向量数据库

本机样例库总量上限 1 MiB，BM25 可以提供可重复、无需密钥的术语检索。中文单字符容易造成偶然匹配，因此降权，并要求有多字符词项的查询至少命中一个多字符词项。代价是同义表达与词序变化仍可能漏召回。下一步应先建立更丰富的独立保留集，再比较向量召回与重排；不能先堆框架后声称提升。

## 引用保证有多强

系统检查编号必须指向当前运行真实检索片段，不能出现 `[99]` 这类不存在的来源。无证据时不展示知识结论。这个检查不识别“正确编号配错误结论”；评测 `source_traceability` 只检查文本和行号一致。语义支持与答案质量需要人工标注或独立评审，不等于 100% 正确。

## 复现顺序

1. `python -m pytest -q` 验证行为与安全边界。
2. `python -m evidence_agent.evaluate --output evaluation/report.json` 复现固定离线检索指标。
3. 免费演示模式导入文档、连续两轮提问、刷新、选择历史轮次、提出 / 放弃 / 确认待办。
4. 配置真正支持 tools 的 Ollama 模型，检查模型轮次 → knowledge_search → 模型回答的轨迹；第二轮追问应在当前会话上下文中改写检索词。
5. 创建待办请求，检查确认前 `GET /api/tasks` 为空，确认后只有一条，再提交同一 ID 应拒绝。不要把模型回复中的“完成”当作真实状态。

真实模型的名称、版本、机器、问题、轨迹与结果应记录在独立报告中；没有运行记录就不能宣称已经实测。
