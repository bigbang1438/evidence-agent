## 实际观察

### 1. 普通中文知识问题

输入：

> 工具调用有哪些安全边界？请检索资料并用编号引用回答。

轨迹只有 `model_plan`，模型没有提出工具调用，因此没有检索来源。服务按照无证据规则拦截知识结论。

### 2. 明确指定检索工具与参数

同一会话输入：

> 请调用 knowledge_search，query 为‘工具调用 安全边界’，根据返回资料回答并标注 [1]。

轨迹为 `model_plan → knowledge_search → model_plan`。检索工具返回 2 条来源，工具 observation 回传模型后出现下一次模型请求。服务返回的本次总耗时为 8,516 ms。

模型最终输出缺少合法引用，服务拦截文本结论。这次观察支持真实模型与检索工具之间的往返路径可以执行，尚未得到符合引用要求的最终知识回答。单次耗时不能代表稳定延迟或性能改善。

### 3. 明确要求提出待办

在同一会话明确要求调用 `task_create`，并提供待办标题。轨迹仍没有工具调用；这次请求没有验证模型提出待确认请求的路径。

## 可支持的结论与限制

- 真实 Ollama 请求、一次实际 `knowledge_search` 执行及 observation 回传已在网页界面观察到。
- 两次知识请求分别因没有证据和没有合法引用被服务拦截；本次没有可接受的最终知识回答。
- 该小模型在这些提示下没有稳定选择工具。自动规划能力、知识回答质量与模型发起待办确认仍需进一步验证。
- 只有同一会话中的 3 次开发冒烟，没有盲测、重复采样、对照模型或独立保留集，不能据此计算可靠成功率或声称质量提升。

项目行为测试中的脚本模型与 HTTP stub 用于验证循环、参数、预算及写入边界；它们不证明真实模型质量。固定词法检索评测另见 [evaluation/report.json](../evaluation/report.json)，其指标不等于上述真实模型问答表现。
